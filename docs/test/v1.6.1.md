## 3. 自然言語 / MCP 参照試験

「GitHub トークンで認証を確認して」という自然言語依頼を想定し、**MCP ツール経由で秘密値をモデルコンテキストに一切入れずに**参照できることを検証（[全ログ](/test/captures/v1.6.1/nl_reference_verification.log)）。

| # | 操作 | 返却内容 | 値の露出 |
|---|------|----------|----------|
| 1 | `usage_guide` | 使い方ガイド | なし |
| 2 | `list_keys` | キー名と保存先のみ | **なし** |
| 3 | `check_key GITHUB_TOKEN` | `{exists:true, app:true}` | **なし** |
| 4 | `get_secret_reference GITHUB_TOKEN` | `keychain://GITHUB_TOKEN` + 使い方 | **なし（参照のみ）** |
| 5 | `doctor` | マスク済み診断 | **なし** |
| 6 | end-to-end `akc run` で GitHub API 認証 | HTTP ステータスのみ | **なし** |

### エンドツーエンド（値を見ずに認証まで）

`get_secret_reference` → `keychain://GITHUB_TOKEN` → `akc run` で子プロセスに注入 → GitHub API を叩き **HTTP ステータスのみ**取得。参照解決の切り分けでは、子プロセスが `ghp_...` 形式の実値を受領し、**親シェルの env は参照文字列のまま**であることを確認（値はモデルに未露出）。

> 補足: 保存済み GITHUB_TOKEN 自体は失効しており API は 401 を返したが、**参照機構（解決→子への注入→親は参照維持）は正常動作**。トークンのリフレッシュはユーザー側メンテナンス事項。

**結論**: AI エージェントが自然言語指示から秘密を扱う際、MCP ツールは名前 / 参照 / マスクのみを返し、実値は `akc run` の子プロセスにのみ渡る導線が確立していることを実証。
